# Learning Method — 技术书籍精读法

> **v1 · 2026-09-13 · 为 [[Ai Agent Book]] 建立，可推广到其他技术书**
> 这是一份**活文档**：每读完一章，在 §6 追加一行，并且**只改一条规则**。不要重写它。

---

## 0. 一句话版本

> **用中文读，合上书，用英文凭记忆写，再回去对照。**

三个动作缺一不可。少了"合上书"，翻译就退化成转录；少了"回去对照"，错误会固化。

---

## 1. 原子循环：每一节

1. **读完一整节**（中文）。不记笔记，最多划线。
2. **切走**——关掉窗口，或滚到看不见的地方。
3. **凭记忆用英文写这一节的笔记。**
4. **回去对照**：补漏、改错。**标记出你没能回忆起来的部分——这是当天最有价值的信号。**
5. **术语校验**：拿不准的英文术语，去 `book-en/chapterN.md` 搜一下官方怎么写。只查术语，不要用它读。每节 ≤5 分钟。

### 三条硬规则

- **永远不复制粘贴。** 如果你在复制，说明你跳过了第 2 步。
- **允许中英混写。** 90% 英文 + 3 句中文但细节完整 ≫ 100% 英文但难点被丢掉。语言纯度是手段，不是目标。
- **标记来源**：`✍️` 我自己写的 · `🧩` 事后补的缺口 · `⏳` 还没读到。这样复习时一眼能看出哪些是真正内化过的。

### 为什么有效

跨语言写作让你**根本没法抄**——必须先真正理解，才能用另一种语言重说一遍。而"合上书再写"把翻译从**转录**升级成**自由回忆（free recall）**，这是记忆研究里效果最强的手段之一。

> 实证（2026-09-13，第 1 章）：同一份笔记里，用中文写的两段（ReAct、MoE）是逐字复制的；所有英文段落都被压缩、重排、提炼过。**同一个人、同一次学习——语言决定了是否加工。**

## 2. 章循环：3 天节奏

| | 内容 |
|---|---|
| **开场 10 分钟** | **冷回忆**：不看笔记，口头/手写回答上一章的思考题。答不出的再翻。这就是间隔复习，不占额外时间。 |
| **Day 1** | 读 + 笔记（前半章），走 §1 原子循环 |
| **Day 2** | 读 + 笔记（后半章）+ 书面回答思考题 |
| **Day 3** | 跑 1–2 个实验 + **给其中一个加一组自己设计的对照** + 把这一章的能力加到贯穿项目上 |

**超时怎么办**：先砍实验的数量，**不要砍"合上书再写"**。方法退化的代价比进度慢的代价大得多。

---

## 3. 贯穿项目：一个 Agent 走完十章

不要做十个互不相干的 demo。**维护一个 agent，每章往上加这一章的能力。**

| 章 | 加什么 |
|---|---|
| 1 | 裸 ReAct loop（不用框架，2 个工具，每轮打印 context 长度） |
| 2 | 上下文压缩 / 前缀稳定性 |
| 3 | 用户记忆 + RAG |
| 4 | 换成 MCP 工具 + 权限分级 |
| 5 | 验证与纠正（Harness） |
| 6 | 扩展观察/动作空间 |
| 7 | 给它写 eval |
| 8 | 后训练（至少跑通一次） |
| 9 | 从轨迹里生成更新 |
| 10 | 拆成多 Agent |

三个好处：能力是**叠加**而非平行的；会逼你理解"这一章解决的是上一章的什么痛点"；30+ 天后手里有一个**能拿出去讲的东西**，而不是十个文件夹。

## 4. 诚实的度量指标

不要问"我记笔记了吗"，要问：

| 指标 | 怎么测 | 健康值 |
|---|---|---|
| **冷回忆率** | 上一章的思考题，不看笔记能答出几道 | ≥ 2/3 |
| **🧩 缺口数** | 每章被指出漏掉的要点数量 | 逐章下降 |
| **自设计实验** | 这一章有没有跑一个**书上没有的**对照组 | ≥ 1 |
| **项目连续性** | 贯穿项目这一章有没有真的动过代码 | 是 |

笔记是副产品。**真正的产出是"合上笔记还能答出来"。**

## 5. 迭代协议 ⭐

**每章结束追加一行日志，并且最多只改一条规则。**同时改两条，你就分不清是哪条起了作用。

### 信号 → 调整

| 观察到的信号 | 大概率的原因 | 调整 |
|---|---|---|
| 又开始复制粘贴原文 | 节奏太赶 | 砍掉当天的实验，或把"节"拆得更小（半节也行） |
| 冷回忆答不出一半以上 | 复习间隔太长，或**笔记写得太全**（笔记越完整越不动脑） | 缩短间隔；或强制笔记只写提纲，细节留空 |
| 🧩 缺口集中在同一类（例子 / 边界条件 / 反直觉结论） | 阅读时的注意力模式有偏 | 读之前先扫一遍小节标题，带着"这节的反直觉结论是什么"去读 |
| 实验只跑不改 | 没有硬要求 | 把"必须加一组自己的 arm"写进 Day 3 |
| 章节持续超时 | 分清是**内容重**还是**方法重** | 内容重 → 调整 §7 预算；方法重 → 简化方法，别简化理解 |
| 英文写得越来越流畅但答题反而变差 | **流畅 ≠ 理解**，出现了"翻译式理解幻觉" | 加一步：每节写完用中文口述一遍核心论证 |

### 每季度问一次

- 这个方法里，哪一条规则我其实从来没遵守过？→ 要么删掉它，要么找出阻力在哪。
- 哪一条带来的收益最大？→ 加强它。

## 7. 本书的时间预算校准

按第 1 章（82KB / 3 天）的实际速度折算。**注意：10 章合计约 36 天，不是 30 天。**

| 章 | 主题 | 体量 | 建议天数 |
|---|---|---|---|
| 1 | Agent 基础 | 82KB | 3 |
| 2 | 上下文工程 | 128KB | **4** |
| 3 | 用户记忆与知识库 | 100KB | 4 |
| 4 | 工具 | 69KB | 3 |
| 5 | Coding Agent 与通用 Agent | 113KB | 4 |
| 6 | 交互 | 94KB | 3 |
| 7 | Agent 评估 | 109KB | 4 |
| 8 | 模型后训练 | 137KB | **5**（体量最大 + 概念最硬） |
| 9 | 持续进化 | 59KB | 2 |
| 10 | 多 Agent 协作 | 102KB | 4 |
| | | **≈993KB** | **≈36 天** |

**现在就承认这 6 天的差额**，比每章偷偷欠一点、到第 8 章崩掉要好。第 4、9 章可以提速，把时间借给第 2、8 章。
